# 迭代路线图

## 里程碑 1：可信角色配置与基础面板

- 建立 TypeScript 严格模式工程。
- 定义统一 `CharacterBuild`。
- 实现米游社本机登录导入，并保留 Enka 备用源。
- 建立 UID `16241824` 的爱丽丝参考基准。
- 复算角色、音擎、驱动盘和无条件 2 件套构成的战前面板。
- 返回逐项计算追踪。

验收：已完成。爱丽丝截图、米游社官方角色详情和新核心复算结果全部匹配；
Enka 服务异常不会破坏米游社导入、本地基准或旧版页面。

## 里程碑 2：数据版本更新

- 以 Nanoka 为静态数据主源，取消旧脚本固定的 `3.0.3` 数据地址。
- 保存原始数据版本和导入时间。
- 生成新增/变更角色、音擎、驱动盘和怪物差异报告。
- 为角色建立 `raw-only / partial / verified` 支持状态。
- 下载版本化的角色、音擎和驱动盘详情 JSON，并从官方原文生成 Buff 审查清单。

## 里程碑 3：规则 Schema 与公共公式

- 建立 Buff Rule Schema 和校验器。（已完成第一版）
- 从 Nanoka 官方文本生成 `partial` 结构化候选，并将无法安全表达的语义转为审查问题。（已完成第一版）
- 迁移驱动盘 2 件套、4 件套与敌人公共公式。
- 实现条件树、作用对象、阶段、叠层和动态表达式。

当前进度：已完成条件树、作用对象、阶段、叠层边界和效果表达式的第一版；已迁移两套经过参考面板验证的无条件 2 件套。异常效果强度、异常/异放独立乘区和怪物乘区的纯公式已实现并有回归测试。旧字典生成的角色 Buff 规则已隔离，当前以 Nanoka 详情原文重新开始审核；未审核条目不进入计算。

本轮审查进展：已完成首批 20 条 Nanoka 角色规则的人工确认迁移。额外能力采用
同属性/同职业/同阵营条件，并支持爱丽丝、凯撒的特殊职业触发；职业和阵营来自
角色详情 JSON，不再维护旧版硬编码阵营表。新规则已通过结构校验，但战斗事件引擎
尚未接入，因此当前不会改变旧版页面的计算结果。

## 里程碑 4：音擎与角色迁移

- 先迁移常用音擎和简单角色。
- 再迁移动态辅助、异常角色和命破角色；首批已先覆盖部分失衡、异常和命破伤害效果。
- 每条 verified 规则必须有正向、反向和边界测试。

当前进度：已加入全角色规则审计命令 `npm run audit:characters`。当前 476 条已登记角色规则均能通过 Nanoka 角色标签构造正向虚拟队伍并在统一求值器中激活；影画、核心等级和条件反例会单独记录。派生异放与独立暴击区已进入主伤害链，剩余55条接入缺口集中在附加伤害实例、失衡值和1条伤害转换。严格模式 `npm run audit:characters:strict` 会在仍有待审语义或主链未消费效果时返回失败，供迁移收尾阶段使用。

## 里程碑 5：新 UI 接入

- UID 输入与角色选择。
- 基础面板差异报告。
- 根据规则自动生成开关、层数和状态控件。
- 新旧引擎并行对照，最后移除旧引擎。

当前进度：新版公式已通过一个很薄的模块桥接层接入原有根目录页面，原界面和旧计算路径保留；新版已覆盖异常类别公式和怪物三段乘区追踪，下一步接入 UID 导入、角色/音擎/驱动盘选择和规则驱动的队伍 Buff 激活。
