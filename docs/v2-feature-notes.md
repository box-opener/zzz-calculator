# v2 词条、真实怪物与 Logo 接入说明

## 有效词条

默认读取米游社 `equip_plan_info.plan_effective_property_list`，按官方属性 ID 转换，不按展示名称猜测；未返回方案列表时使用驱动盘副属性的 `valid` 标记。显式空方案仍为空；缺少方案时显示“职业预设”，用户可修改并恢复米游社默认方案。

计入总数的可选项是攻击力%、生命值%、防御力%、暴击率、暴击伤害和异常精通。固定攻击、固定生命和固定防御以小字附在对应百分比项之后，非命破角色的穿透值单独作为小词条显示；这些小词条不计入总数。数量读取当前副词条 `roll_count`，包括初始出现和每次强化，不包括主属性、套装、音擎及角色面板。

例如攻击力%合计 10 次、固定攻击合计 3 次，显示为 `10 +3`，其中 `+3` 为小字，攻击有效词条总数仍为 10。米游社获取时的 `valid_property_cnt` 作为历史对照，当前统计随装备和自定义方案实时变化。自定义方案保存在浏览器 `zzz-effective-stats-v1`，角色配置 v2 新增可选 `effective_substats` 字段；旧配置继续兼容。

## 新增一条的收益

计算请求的可选 `substat_analysis` 列表包含至多三名不重复的当前队员。服务端对每种 S 级副词条分别构造一条静态 Build 贡献，执行完整计算管线，比较本次主控招式总伤害。原装备、套装数量、已选规则和场景保持不变，角色转化及队友面板联动重新求值；没有根据最终攻击力直接乘一个近似百分比。

所有可用副词条都提供比较，显示有效、小词条或未选分类；命破角色排除穿透值建议。每次仅增加一种、一条，不是在一张真实驱动盘上继续强化，因此已满 9 次的盘也可进行理论收益比较。界面以期望伤害展示，逐项展开可看不暴击和满暴击。基准为零时绝对增益仍可显示，百分比为空；基准或对比结果不完整时不声称零收益。配置变化后标记需要重新计算。

暴击概率仅在暴击区结算时限制为 0–100%；原始角色面板不裁剪，溢出属性转化仍读取原始值。此约束避免“已满暴击再加一条”产生虚假的概率收益。

## 真实怪物

源为 [Nanoka 怪物页](https://zzz.nanoka.cc/monster/)及[正式版 3.2 目录](https://static.nanoka.cc/zzz/3.2/monster.json)，数据保存于 `core/data/enemies/catalog.json`，记录版本、读取时间、每个条目的源地址和页面地址。当前快照为 306 个目录条目、653 个具有属性的变体；266 个条目可选择。多个相同展示名以目录 ID 和具体变体区分，默认目标为目录 `300021` 的“卫士Ⅱ型”默认变体 `11051`。

防御 = 基础防御 × 对应等级成长曲线值 / 曲线 ratio；保留计算精度，显示值可以格式化。伤害抗性读取 `*_damage_res / 10000`，不以异常积蓄抗性或失衡抗性替代；基础失衡倍率读取 `1 + stun_damage_taken_ratio / 10000`。切换怪物/变体会恢复其默认属性；改等级默认重算防御，手动改防御后停止自动覆盖，用户可恢复自动更新。

当前源数据仅提供物理、火、冰、电、以太、风的伤害抗性，未提供流明抗性。流明伤害计算前要求用户填写或确认手动值，不能声称该值来自怪物源。40 个条目没有 `monster_info`，其中包含未命名占位条目以及“渡鸦无人机”“渡鸦无人机·活化型”和“巡逻者轻型”，保留来源但不提供计算选择。正式 3.2 的卫士Ⅱ型只有 `11051`、`11052` 两个变体，测试版新增变体不会混入该快照。

刷新数据可运行 `python scripts/sync_nanoka_enemies.py --version 3.2`，核对数据差异后再提交；脚本只在全部读取成功后替换旧目录，不会自动切到 Nanoka 默认的测试版。源缺失的动态 Boss 阶段、防御切换或特殊机制不由怪物名称推断；本次普通目标选择提供源静态属性和手动场景输入。

## Endgame 实施

用户于 2026-10-13 审阅并同意 [执行方案](v2-endgame-plan.md)。已接入危局与式舆，打包正式版本 3.2 的 47 个危局期数、62 个式舆目录记录（含常驻节点），共 109 份完整详情。当前正式期数按国服 UTC+8 判定；未来正式数据明确标为即将开放，不混入测试版本。危局接口为 `.../3.2/boss.json` 与 `.../3.2/zh/boss/{season_id}.json`，依据其页面模块的实际引用核对。

目录保留动态数量的防线/试炼、子房间、目标与波次数。例如 62058 的第五防线为三个房间，不固定上下半。源详情只提供房间合并目标，未提供逐波的目标关联，所以界面展示波次数并选择本次单个目标，不虚构波次 ID。危局的困难模式对应源 `zone_type=1002`，中文标签沿用页面的“困难模式”。生命档位读取对应 BossAdjust 表：普通从 1001、困难从 1301 起逐档读取，HP 为 `floor(房间基础HP × hp/10000)`，不把生命档位当作战斗等级。源的房间 `stats.defence` 已经是该期目标最终默认防御，不再重复乘基础成长曲线。抗性、失衡倍率只从同内部 ID 的真实怪物变体读取，源缺失时允许显式手动覆写并记录来源。

249 条非空 Buff 原文均有明确审核映射或未决标记；程序不通过文案正则推导效果。已审阅文本的 SHA256 单独保存在 `reviewed-evidence.json`，同 ID 的文本改变也不会悄悄使用旧数值。场地 Effect 使用独立 `environment` 来源且无角色 owner；全队面板按命名接收角色编译，个人触发状态逐队员选择，职业限制由正式角色定义判定。面板、普通增伤、异常/紊乱/异放/乱流/贯穿专属乘区、减防/减抗与失衡易伤均沿用项目规则。局内攻击百分比以初始攻击为基准（规范 8.4），新增副词条仍以白值组装局外面板，两者不混用。失衡易伤“提升 N%”按现有易伤节点增加 N 个百分点，不在计算器外额外乘场地倍率。

触发状态默认未生效，叠层从零开始。场地规则默认启用，可单独关闭作对照；非法层数、跨期 Buff、外部规则 ID 和无关队员状态由服务端拒绝。残翳与裂伤互斥，并分别受非失衡/失衡状态过滤。本版一次计算比较零个或一个可选增益；这属于首期产品能力限制，原数据没有提供跨版本通用选择上限，未将“一种”推定为所有未来玩法的规则。计分、回能、恢复速度与异常积蓄耗时等过程条款保留原文，不模拟评分与全程战斗。

`GET /api/v1/endgame/seasons?mode=...`、`GET /api/v1/endgame/seasons/{mode}/{season_id}` 与 `POST /api/v1/endgame/editor` 使用本地快照。计算提交 `endgame_selection` 命名对象；场景编译到正式规则中，白盒显示来源，每次词条比较复用同一选择且只改变 Build。输出 `scenario_provenance` 保存模式、期数、目标、Buff、状态、数据摘要及覆写来源。`zzz-scene-config-v1` 文件单独保存目标和场地，导入校验摘要，队伍/装备保持当前角色配置；同队伍、装备与招式下重现同一场景，不声称该文件保存整场战斗。

更新方式：`python scripts/sync_nanoka_endgame.py --version 3.2` 下载到 `.cache/nanoka-endgame/3.2`；审核差异、更新映射和证据、通过测试后再发布到 `core/data/endgame/3.2`。脚本不会自动重写审核证据、启用新 Buff 或切换测试版本。
