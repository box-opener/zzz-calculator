# UID 导入设计

## 数据提供者

首选数据源改为米游社官方养成指南。它需要玩家登录，因此采用本机浏览器授权：

```text
npm run import:miyoushe -- 16241824
```

不指定角色 ID 时，会读取账号全部已拥有角色，并按每批最多 10 名角色请求完整详情。

指定角色 ID 后，导入器会在登录完成后自动请求该角色详情，例如爱丽丝：

```text
npm run import:miyoushe -- 16241824 1401
```

导入器打开独立的 Chrome 窗口，由玩家自行完成登录。代码只监听官方页面返回的
`avatar_basic_list` 和 `batch_avatar_detail_v2` 角色数据，不读取、不打印、不导出
Cookie。浏览器会话仅保存在被 `.gitignore` 排除的 `.cache/miyoushe-browser/`。

UID 用于校验响应归属，不用于绕过米游社登录查询其他玩家。

Enka 保留为无需登录的备用数据源：

```text
GET https://enka.network/api/zzz/uid/{uid}
```

它是可替换的数据提供者，不是项目的领域模型。代码通过 `UidProvider` 接口隔离，未来可以增加其他来源或读取用户上传的原始 JSON。

## 缓存与失败策略

- 请求设置项目专属 `User-Agent`。
- 成功响应按接口 `ttl` 缓存。
- 重复请求优先读取未过期缓存。
- 服务维护或限流时保留旧缓存，并返回明确警告。
- 不枚举 UID，不批量抓取玩家数据。
- 只保存计算所需的公开展示数据。

## 当前实测

2026-08-14 请求 UID `16241824` 时，Enka 绝区零接口返回 HTTP `424`：上游数据服务暂时不可用。

因此第一阶段支持：

1. 米游社本机登录后导入完整角色数据。
2. Enka 在线公开展示导入及旧缓存。
3. 用户参考截图建立的标准化 fixture。

米游社原始响应和标准化账号配置都会保存在 `.cache/uid/`。音擎没有“突破次数”
这一构筑字段，标准模型不保存它；等级已经足够满足当前面板计算。

接口不可用不应阻塞计算引擎开发。
